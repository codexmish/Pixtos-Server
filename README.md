# Pixtos — Backend

A REST API for a personal photo and video library. Users upload photos and videos, find them with search (including AI-detected objects), keep favorites, group them into albums and use a trash with restore — like a small Google Photos.

This repository is the **backend (v1)**. The frontend is built separately: [Pixtos-Client](https://github.com/codexmish/Pixtos-Client).

## Features (v1)

- **Authentication** — signup with email OTP verification (stored in Redis), resend OTP with a 1-minute cooldown, sign in, refresh token, logout, forgot / reset password, change password.
- **JWT in httpOnly cookies** — access and refresh tokens are never exposed to JavaScript.
- **Profile** — update name, upload avatar to ImageKit (the old avatar is removed).
- **Media upload** — up to 20 photos / videos at once, stored on ImageKit. Thumbnails are generated by ImageKit (a frame from the video for videos).
- **AI tags** — every uploaded photo is auto-tagged (for example `bird`, `beach`, `car`), so search finds photos by what is in them, not only by file name.
- **Library** — newest first, filter by photo / video, search by title or AI tag, favorites only.
- **Favorites** — favorite one item, or many at once.
- **Trash** — move one or many items to trash, restore, delete permanently, empty trash. A permanently deleted file is removed from ImageKit and from every album.
- **Albums** — create (optionally with photos), add photos, remove a photo, delete an album. Photos stay in the library when an album is deleted.
- **Storage stats** — used storage, photo / video / favorite / album counts.

## How It Works

### Signup flow

```
1. User signs up                          POST /auth/signup
   -> password is hashed, signup data + a 6-digit OTP are saved in Redis (5 minutes)
   -> OTP is emailed
2. (optional) a new code                  POST /auth/resend-otp   (once per minute)
3. User enters the code                   POST /auth/otp-verify
   -> the account is created in MongoDB, Redis data is removed
   -> accessToken + refreshToken cookies are set, a welcome email is sent
```

The account is created **only after** the OTP is verified, so unverified signups never reach the database.

### Upload flow

```
1. Files arrive as form-data                POST /media/upload   (field "media")
2. Multer keeps them in memory (images / videos only, 100 MB each, 20 files)
3. Each file is uploaded to ImageKit
   - photos  -> /my-photos  (with google-auto-tagging, up to 10 tags)
   - videos  -> /my-videos
4. A thumbnail URL is built from the ImageKit file path
   - photo: <endpoint>/tr:w-400/<path>
   - video: <endpoint>/tr:w-400/<path>/ik-thumbnail.jpg
5. A Media document is saved with url, thumbnail, size, format, width, height, duration and tags
```

### Trash flow

```
Library ──trash──► Trash ──restore──► Library
                     │
                     └──delete / empty trash──► removed from ImageKit, MongoDB and every album
```

Items in trash are hidden from the library, favorites, albums and storage stats.

### Data model

| Model | Purpose |
|---|---|
| `User` | Name, email (unique), password (hidden), verified flag, avatar (+ hidden ImageKit file id), role (`user` / `admin`). |
| `Media` | Owner, title, url, thumbnail, ImageKit file id, size, format, type (`image` / `video`), width, height, duration, AI tags (`objects`), favorite flag, trash flag + trashed date. |
| `Album` | Owner, title, description, list of media ids. |

## Getting Started

### Requirements

- Node.js 20+
- MongoDB database
- Redis
- ImageKit account
- SMTP account (for example Gmail with an app password)

### Install and run

```bash
git clone https://github.com/codexmish/Pixtos-Server.git
cd Pixtos-Server
npm install
# create a .env file in the root (see the table below)
npm run dev
```

The server runs on `http://localhost:8000` and the API on `http://localhost:8000/api/v1`.

> The server checks every environment variable at startup. If one is missing or empty, it prints which ones and stops.

## API Documentation

### Conventions

**Base URL:** `http://localhost:8000/api/v1`

**Authentication:** sign in (or verify OTP) sets `accessToken` and `refreshToken` as **httpOnly cookies**. Send requests with credentials:

```js
fetch(url, { credentials: "include" });          // fetch
axios.get(url, { withCredentials: true });        // axios
ofetch(url, { credentials: "include" });          // ofetch
```

**Access levels used below**

| Label | Meaning |
|---|---|
| Public | No login needed. |
| Login | Any signed-in user. Users can only see and change their own media and albums. |

**Success response**

```json
{
  "success": true,
  "statusCode": 200,
  "message": "Media get successfully",
  "data": {}
}
```

**Error response**

```json
{
  "success": false,
  "statusCode": 400,
  "message": "Invalid media id"
}
```

- Validation errors return `400` with the first problem as the message.
- An invalid id in the URL (for example `/album/abc`) returns `400` with `Invalid _id`.
- Too many requests returns `429` with `Too many requests, please try again later.`

**Ids** are MongoDB ObjectIds (24 hex characters).

### How to read each endpoint

Every endpoint below starts with a numbered heading and ends with a horizontal line. Each one lists:

- **Access** — who can call it.
- **URL params** — values inside the URL (like `:id`).
- **Query params** — values after `?` in the URL.
- **Request body** — JSON you send (or form-data for file uploads).
- **Cookies** — `accessToken` / `refreshToken` are sent automatically by the browser when `credentials: "include"` is used.

If a section says **None**, nothing needs to be sent for it.

### Auth `/api/v1/auth`

---

#### Auth 1. Sign up

`POST /api/v1/auth/signup`

**Access:** Public · **Rate limit:** 5 requests / 10 min

**URL params:** None · **Query params:** None · **Cookies:** None

**Request body**

| Field | Type | Required | Rules |
|---|---|---|---|
| `name` | string | Yes | At least 3 characters |
| `email` | string | Yes | Valid email (stored in lowercase) |
| `password` | string | Yes | 8–32 characters |

```json
{
  "name": "Rahim Uddin",
  "email": "rahim@example.com",
  "password": "Pass@1234"
}
```

**Response:** `200` — an OTP is emailed. It is valid for 5 minutes. The account is created only after OTP verification.
**Errors:** `400` an account with this email already exists.

---

#### Auth 2. Verify OTP

`POST /api/v1/auth/otp-verify`

**Access:** Public · **Rate limit:** 5 failed requests / 10 min

**URL params:** None · **Query params:** None · **Cookies:** None

**Request body**

| Field | Type | Required | Rules |
|---|---|---|---|
| `email` | string | Yes | The email used in signup |
| `otp` | string | Yes | Exactly 6 characters |

```json
{
  "email": "rahim@example.com",
  "otp": "483920"
}
```

**Response:** `201` — the account is created, `accessToken` and `refreshToken` cookies are set and a welcome email is sent. No user data is returned; call **Auth 10** to get it.
**Errors:** `400` email already verified · OTP expired · wrong OTP.

---

#### Auth 3. Resend OTP

`POST /api/v1/auth/resend-otp`

**Access:** Public · **Rate limit:** 5 requests / 10 min + 1 request per minute per email

**URL params:** None · **Query params:** None · **Cookies:** None

**Request body**

| Field | Type | Required | Rules |
|---|---|---|---|
| `email` | string | Yes | The email used in signup |

```json
{
  "email": "rahim@example.com"
}
```

**Response:** `200` — a new OTP is emailed and the previous one stops working. The signup data gets 5 more minutes too.
**Errors:** `400` signup expired or email already registered · `429` asked again within 1 minute.

---

#### Auth 4. Sign in

## Security

- Passwords hashed with bcrypt; never returned in any response.
- JWTs only in httpOnly cookies (`secure` + `sameSite=none` in production).
- Every request body is validated with Zod; unknown fields are stripped.
- Every media and album query is filtered by the owner, so users can only see and change their own data.
- Rate limits on auth routes, avatar upload and media upload; 1-minute cooldown for OTP resend. `trust proxy` is on in production so limits use the real user IP.
- OTPs live in Redis for 5 minutes; unverified signups never reach the database.
- Uploads are checked for type and size (images / videos up to 100 MB, avatars: images up to 5 MB).
- Helmet security headers, CORS limited to the frontend origin.
